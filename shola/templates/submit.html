Get human answers for your data

Upload the items, choose the languages, and speakers here will work through them a few at a time. The results are public, as everything on SHOLA is.

The file

One CSV per language, saved as CSV UTF-8 so ɛ, ɔ and ŋ survive. Two shapes are accepted:

text,option1,option2,option3
Where is the market?,Ɛhe na dwaso wɔ?,Dwaso wɔ he?,Dwaso no wɔ he?

…for volunteers to choose between, or a single column…

text
Where is the market?

…for volunteers to type the answer themselves. A header row is optional. Two to five options per line; every line must have options or none of them may.

You do not choose between these — the file decides. With options, answers can be verified by agreement; without, they are collected as contributions. Either way volunteers can write their own answer, and that wording becomes an option for the next speaker.

This is the title they choose from, so write it as the task: “Translate everyday Ghanaian words”, “Read these sentences aloud in Ewe”.

What is one item?
{% for code, label in formats.items() %} {% endfor %}

An item stops going out once it reaches this, and your project is finished when every item has. Five is the default across SHOLA.

If your file has no options, this is simply how many separate answers to collect for each item — we spread the work so every item gets that many. Nothing is verified: typed answers cannot be checked against each other.

If your file carries options, it counts matching answers — this many speakers tapping the same option is what verified means, and higher is stronger evidence. Volunteers can still write their own answer, which becomes an option for the next speaker; it only counts towards verification once others tap it.
